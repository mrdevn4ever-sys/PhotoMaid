## Prioritized actionable findings

### P1 — fix before accepting functional or security preservation

1. **Archive can crash after a skipped input.** `PhotoMaid/Infrastructure/Archive/ArchiveService.swift:15-17,29,43-54`: enumerate the input ID list, skip missing/unreadable IDs without appending, then index the shorter `journal.entries` using the original input index. A missing first input followed by a valid second produces `entries[1]` for an array of length one; even the catch path repeats the invalid index. Fix: record `entryIndex = journal.entries.count - 1` immediately after append and use it for every subsequent mutation. Test missing-first, missing-middle, revoked-access and write-error sequences. The newer branch already implements this exact fix at `ArchiveService.swift:30-31,45-56`.

2. **Claimed features are unreachable, not merely cosmetically unfinished.** `StudioView.swift:18-20`, `ToolsView.swift:6,77-85`, `Routes.swift:34,78,118,121`, `RootView.swift:164`: five standalone tools, PDF Studio and scanner have no production entry. Add explicit localized navigation; wire all tool kinds, PDF Studio and supported scanner; preserve a navigation reachability test independent of view declarations. No app PDF annotation/signature/OCR-text-layer pipeline was found, so these cannot be included in a completed feature-preservation claim. This issue also remains in the inspected newer branch's Studio entry structure (`StudioView.swift:19-21`); adopting the whole branch would not automatically repair it.

3. **OCR/analysis cache is included in OS backup despite “never backed up” comments and policy.** `Persistence/KeyValueStore.swift:33-36` places caches, including recognized text, in CDKeyValue; `SmartReviewView.swift:72` writes there. `Persistence/CoreDataStore.swift:8-11,26-34,63-68` puts the entire SQLite store in backed-up Application Support with no separate cache exclusion. Excluding analysis from the user-exported JSON does not exclude SQLite rows from device/iCloud backup. Fix: move derived results to an excluded cache database/directory, migrate/purge existing rows, and explicitly distinguish OS backup from app JSON backup in the data map. Verify actual backup membership on Apple hardware. This is a policy/retention mismatch, not a claim of an attacker bypassing iOS encryption.

4. **Editor replacement bypasses the shared cleanup journal and allowance.** `Features/Editor/EditSaver.swift:65-78` directly calls `library.delete`, unlike `AppModel.swift:394-420` which reserves quota and persists an operation intent before system deletion. Consequently replacement removals do not follow the stated “every system operation is journaled” invariant (`docs/PRODUCT_CONTRACT.md:48-51`) and cannot be reconciled through that mechanism after a crash. The `.partial` case is also treated as replaced without checking whether the original is in its removed set. Fix: define an explicit replacement cleanup operation with durable intent/reconciliation and decide/document whether it consumes the shared daily allowance; check the exact removed ID. Test copy success + deletion refusal, partial-empty, and process termination between PhotoKit completion and bookkeeping. Do not silently change the business rule.

5. **Deletion completion uses weaker evidence than recovery when permission changes.** `Infrastructure/PhotoLibrary/PhotoLibraryService.swift:406-409` infers all missing IDs as removed after performChanges. By contrast `probe` at 370-381 correctly makes missing IDs unknown under limited access. Original `ids` can include assets not submitted because they were not fetched/deletable (391-394). Fix: reconcile only submitted IDs, retain unknown status when authorization becomes restricted/limited, and avoid treating access loss as removal. Test successful subset + inaccessible IDs, scope shrink during dialog, cancel, and delayed PhotoKit visibility. This is a source inconsistency; actual iOS interleaving has not been reproduced.

6. **Newer vault branch's public visibility boundary fails open on unreadable/corrupt concealment, and failures are swallowed.** BRANCH ONLY: `Infrastructure/Vault/VaultConcealment.swift:23-25,36-53,114-129` explicitly treats unavailable/invalid `c.json` as no concealed IDs; `isConcealed` returns false and `visible` returns all input. `PhotoLibraryService.swift:257-271` relies on this boundary for public asset lookup. Analysis alone has a fail-closed `analysisReady` guard (57-67), not the rest of the app. `VaultStore.swift:836-840` ignores failed persistence while reporting imported items and proceeding; `commitSnapshot:468-471` similarly ignores file-concealment updates. Thus source does not justify a blanket “fail closed” isolation claim. Fix: represent unknown/corrupt distinctly from empty, block public affected reads until repair, and transactionally require persistent concealment before reporting import/concealment success. Test corrupt/truncated/inaccessible list and disk-write failure while originals remain in Photos. This is a confirmed source behavior, not an assertion that encrypted payloads can be decrypted without a code. Do not silently transplant the security subsystem into main.

### P2 — correctness, performance, truthful result handling

7. **ResourceStream is not bounded despite its comment.** `Infrastructure/PhotoLibrary/MediaSizer.swift:142-158,169-179`: callbacks append to an unbounded `[Data]`; the consumer's maxLength only splits after buffering, with O(n) removeFirst/insert. Large resources can accumulate faster than hashing consumes them. Fix bounded producer/consumer buffering with cancellation and memory high-water tests; do not block PhotoKit callbacks in a way that deadlocks completion. Duplicates also start detached scans at `DuplicatesView.swift:133-139`; cancelling the outer stored Task does not itself cancel that detached child, so wire cancellation explicitly.

8. **Analysis lifecycle performs excessive and stale work.** `LocalPhotoAnalyzer.swift:17-34` loads full original data and always performs classification, OCR and feature prints; `BatchProcessor.swift:10-20` enables iCloud requests without bounded-size preview or timeout/cancellation bridge. `SmartReviewView.swift:28,65-73` creates an unstructured Task with no on-disappear cancellation, progress, resumable controller, or generation/privacy invalidation. Cache entries have modification dates but `SmartReviewView.swift:14-18,45,48` does not validate them against current media. Fix a lifecycle-owned bounded request pipeline, selected-feature-only processing, explicit cloud policy, invalidation on permission/visibility changes and deterministic stale-result tests. The newer branch adds AnalysisController/Database/Runner/ImageLoader rather than merely a new view; evaluate as a subsystem, not a single-file cherry-pick.

9. **PDF save is temporary and import lacks security-scoped lifetime.** `Infrastructure/Documents/PdfServices.swift:34-36,48-50` writes tmp URLs, while UI labels say Save. Scanner similarly reports saved at `DocumentScannerHost.swift:31-39` before the user completes the share activity. `PdfStudioView.swift:45-48` opens external URLs without starting/stopping security-scoped access or making a coordinated local copy. Fix durable unique documents with verified nonempty writes and honest success filenames; stage or hold scoped PDF access for lazy PDFKit reads. Add cancelled export, provider-denied, empty PDF, relaunch and name-collision tests. The newer branch contains durable-PDF changes; main does not.

10. **File deletion loses provider errors and validates only before coordination.** `Infrastructure/LocalFiles/ConnectedSources.swift:249-255` skips the entire source based on folder isWritable, swallows source/remove/coordinator errors, and does not revalidate the coordinated target's regular-file/symlink status inside the accessor. `removeItem` itself accepts directories recursively; the pre-coordination check alone is weaker than the documented regular-file-only invariant. Fix per-file access attempts, validation inside the accessor, safe domain/code error reporting and tests with provider refusal or replacement targets. No arbitrary-path exploit was reproduced. The newer branch implements per-file validation/error reporting at `ConnectedSources.swift:259-310`; use that bounded fix as review material rather than importing unrelated monetization/vault changes.

11. **Restore says done after ignored persistence failures.** `Features/Archive/BackupView.swift:72-94`: decision wrappers return Void and handle errors internally; tag/note/basket results are discarded, then the plan is cleared and success toast shown regardless. Fix result collection and a resumable partial-restore summary; only clear successful work. Test injected ledger and KV write failures midway through mixed decisions/notes.

12. **Archive “write list” toggle has no implementation.** `ArchiveView.swift:26` changes `ArchiveOptions.writeList`; a whole-source search finds no consumer beyond that setting/declaration (`Sources/PhotoMaidCore/Archive/Archive.swift:73-74`). The journal is saved internally only (`ArchiveView.swift:56`). Implement the selected target manifest with durable success/error reporting, or remove/disable the claim explicitly. Separately, ArchiveService copies only the first PhotoKit resource and hashes a resource selected by another rule (`ArchiveService.swift:17,39`, `MediaSizer.swift:135-138`); do not market this as a verified complete Live Photo/RAW+JPEG archive until resource-set preservation is implemented and tested.

13. **Privacy shield does not support its unconditional app-switcher guarantee.** Main `RootView.swift:55-65` shields only on background, not inactive; the shield is inside the presenting ZStack while full-screen covers are attached above it (`28-30,42-45`). `docs/PRIVACY_DATA_MAP.md:21` instead says whenever not active. Fix a scene-level cover over all presentations and test app-switcher snapshots with viewer/editor/share sheets visible. Newer branch adds a top-level UIWindow PrivacyCover (`RootView.swift:77-83,195-212`). Snapshot timing is a device test, not proven disclosure in this audit.

14. **Read readiness and queue work are coupled to StoreKit/network and full snapshots.** `AppModel.swift:157-167` awaits purchase refresh before publishing ledger read state; `FeedViewModel.swift:91` captures records before waiting for initial library loading. A feed can build against an earlier empty projection, and full ledger/state derivation on every decision (`AppModel.swift:268-287,341-343`) does not scale with long history. Fix explicit ledger-ready gating, initial publish before product fetching, generation-tagged background queue computation/coalesced updates. The newer branch has dedicated readiness/coalescing changes; preserve item/revision invariants while porting.

### P3 — documentation and acceptance hygiene

15. **Documents contradict actual policy/code.** `docs/MONETIZATION.md:7-25` says 15/RevenueCat/rewarded; `docs/PRODUCT_CONTRACT.md:9,19,55-59` says no Vision and diagonal custom-date gesture; authoritative CLAUDE/E1-E15 and code instead use 20/direct StoreKit/local Vision/no diagonal gesture/no ads. `docs/RELEASE_BLOCKERS.md:7` still says 19 views absent, while `IMPLEMENTATION_STATUS.md:35` says those views exist. Do not infer secure memory zeroization, screenshots prevented, or Apple hardware-backed PIN retry throttling from these mechanisms. See P1 finding 6 for the surviving isolation weakness.
- **Public projection isolation is implemented broadly on branch.** Filtered PhotoKit entry points, cache purges, history/backup/draft/source filtering, source-derived output tracking and top-level privacy cover are absent from main. Ordinary main hide/exclude settings are not substitutes. Branch documentation admits legacy untraceable originals/outputs and new-device ID limitations (`docs/VAULT_SECURITY_IMPLEMENTATION_STATUS.md`, boundaries section).
